# Repository Guidelines

Публичное название проекта — Tabest — Fuzzy Tab Finder, коротко Tabest. Лицензия —
MIT. Это расширение для Firefox и Zen с поиском вкладок в отдельной служебной
вкладке и управлением в стиле Telescope/Vim. Этот файл —
единая точка входа для агентов; корневые `AGENTS.md` и `CLAUDE.md` ссылаются сюда.

## Обязательные правила

Перед изменениями прочитай все четыре документа:

1. [Рабочий процесс и разрешения](rules/workflow.md).
2. [Архитектура и стиль кода](rules/architecture.md).
3. [Тестирование и проверка](rules/testing.md).
4. [Интерфейс и клавиатурное управление](rules/interface.md).

Все правила применяются ко всему проекту, а не только к каталогу `.agents`.

## Предпочтения пользователя

- Проверяй каждое изменение. Подбирай тесты под затронутые сценарии и сообщай,
  что действительно выполнено, что не прошло и что проверить не удалось.
- Не выполняй никакие команды Git без явного разрешения пользователя, включая
  команды только для чтения. Не создавай коммиты, ветки или PR автоматически.
- Не затрагивай повседневную сессию браузера. Проверки выполняй в изолированном
  экземпляре Zen с отдельным профилем.
- Сохраняй пользовательские изменения и настройки. Не перезаписывай привязки
  клавиш и не удаляй посторонние файлы ради удобства реализации.
- Разделяй наблюдаемый симптом, воспроизведённый сценарий, гипотезу и доказанную
  причину. Не называй защитное изменение подтверждённым исправлением, если исходный
  баг не удалось воспроизвести.

## Как работать с инструкциями

Сначала уточни задачу по текущему коду и этим правилам. Анализ или диагностика сами
по себе не означают разрешение внедрять исправление. При реализации меняй только
необходимое и проверяй как новый сценарий, так и связанные регрессии.

В итоговом сообщении кратко опиши результат, выполненные проверки и оставшиеся
ограничения. С пользователем общайся по-русски, если он не попросил иначе.

Обновляй соответствующий документ в `rules/`, когда меняются архитектура, команды
или согласованное поведение. Корневые файлы оставляй короткими указателями.
Не придумывай соглашения о коммитах и не исследуй историю Git без разрешения.
