# Тестирование и проверка

## Обязательный минимум

Каждое изменение должно иметь проверку, соответствующую риску. После изменений
кода запускай `npm test` и `npm run build`. Для исправлений добавляй регрессионный
тест, где это возможно. Для документации проверяй ссылки, пути и указанные команды;
не выдавай проверку Markdown за проверку поведения браузера.

Модульные тесты используют `node:test` и `node:assert/strict`; файлы называются
`tests/*.test.ts`. `npm test` явно задаёт `--test-isolation=none`: сохраняй этот
режим и проверяй, что выполняются отдельные тесты, а не только учитываются файлы.
Числовой порог покрытия сейчас не настроен — не выдумывай его.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm test` | Модульные тесты контроллера, поиска, фильтров, клавиш и preview. |
| `npm run build` | Проверка типов и сборка расширения в `dist/`. |
| `npm run dev` | Пересборка расширения при изменениях исходников. |
| `npm run preview` | Vite-сервер с деморежимом, без переключения реальных вкладок. |
| `npm run test:zen` | Сборка; preview, геометрия, хоткей и очистка дублей в Zen. |
| `npm run test:zen:deletion` | Сборка; удаление, выбор и повторное открытие picker. |
| `npm run test:zen:filters` | Сборка; фильтры, клавиши, сохранение и адаптивная вёрстка. |
| `npm run test:zen:ui` | Сборка; компактный вид, preview, favicon, подсказки, сохранение и узкое окно; снимки в каталоге отчёта. |
| `npm run test:zen:suggestions` | Сборка; реальный индекс истории на синтетических данных, optional history, ранжирование, выбор, открытие, удаление и узкое окно. |
| `npm run test:zen:query` | Сборка; нативный Alt+Enter, адрес/поиск с тестовым движком, Enter, Normal, клики, переназначение и узкое окно. |
| `npm run test:zen:sessions` | Сборка; создание/перенос/переименование сессий, общий поиск, Ctrl+T, наследование, undo-close, приватность, перезагрузка и узкое окно. |
| `npm run lint:extension` | Проверка manifest и расширения через `web-ext`. |
| `npm run package` | Сборка и упаковка через `web-ext` в `artifacts/`. |

Команды с `npx --yes web-ext` могут требовать сеть и загрузку пакета. Не обходи
сетевые ограничения; сообщай, если эти проверки выполнить невозможно.

## Проверки в браузере

Для UI, хоткеев, preview и жизненного цикла вкладок запускай соответствующие
Zen-сценарии, а не только моки. Скрипт `scripts/zen-smoke.mjs` копирует установку
браузера и сборку в отдельный временный каталог и создаёт свежий профиль.
Бинарник по умолчанию: `/opt/zen-browser-bin/zen`; другой можно задать через
`TABEST_ZEN_BINARY` (старое `TELESCOPE_ZEN_BINARY` остаётся запасным вариантом).

Не меняй установленный браузер и не используй основной профиль пользователя.
Проверяй пустые результаты, длинные заголовки, много вкладок, узкий экран,
повторные нажатия и сохранённые пользовательские настройки по применимости.
В отчёте указывай выполненные команды и ограничения. Не утверждай, что баг
воспроизведён или исправлен, если проверен только похожий сценарий.
