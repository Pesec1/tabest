# Рабочий процесс и разрешения

## Границы задачи

- При запросе анализа сначала исследуй и объясни; не внедряй исправление без
  запроса на изменение. При запросе реализации доводи работу до проверки.
- Перед редактированием читай затронутые файлы. Ищи через `rg` и `rg --files`.
- Используй `apply_patch` для правок. Сохраняй несвязанные изменения пользователя.
- Не меняй зависимости, разрешения расширения или архитектуру без необходимости
  для задачи; объясняй значимые изменения.
- Если запись запрещена средой, сообщи точный путь и ограничение. Не обходи защиту
  через другие инструменты, смену прав или перемещение защищённых каталогов.

## Git — только после разрешения

Без явного разрешения пользователя не запускай **никакие** команды Git, включая
`git status`, `git diff`, `git log` и `git show`. Не обращайся напрямую к `.git`
для получения тех же сведений в обход этого ограничения.

Разрешение на просмотр не означает разрешение на запись: `add`, `commit`,
`push`, создание веток, worktree и PR требуют соответствующего согласования.
Не выполняй разрушительные операции автоматически. Если Git недоступен или
не разрешён, проверяй результат чтением файлов и тестами, не заявляя о чистоте
рабочего дерева.

## Диагностика и данные

- Строй выводы на коде, точном воспроизведении и журналах, а не на предположениях.
- При странном поведении хоткея проверяй конфликт с командами Zen, модами и другими
  расширениями. Ранее восстановление вкладок оказалось конфликтом хоткея.
- Снимки вкладок, адреса, заголовки и пользовательские журналы могут быть личными.
  Не отправляй их наружу и не включай в документацию или фикстуры.
- `scripts/trace-tabs.js` — ручной диагностический инструмент, не часть сборки.
  Его отчёт использует условные идентификаторы страниц вместо адресов.
- Не очищай профили, вкладки, настройки или временные артефакты пользователя.
